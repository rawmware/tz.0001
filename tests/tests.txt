# Tests

## Test 1 - Open Home by default after reload [sanity]
Viewport: desktop
Covers: primary Home route, fresh-load behavior, portfolio landing content
Description: Verifies every fresh visit opens the public-facing Home experience instead of Chat.

Steps:
1. Open the application
2. Select Chat
3. Refresh the page

Expected: Home is selected and the "Ideas made real" landing content is visible after refresh.

## Test 2 - Navigate between Home and Chat on mobile
Viewport: mobile
Covers: hamburger navigation, Home label, in-app view switching
Description: Verifies the mobile menu clearly calls the landing page Home and preserves access to Chat.

Steps:
1. Open the hamburger menu
2. Select Chat
3. Open the hamburger menu and select Home

Expected: The menu contains Home, Chat, and Monitoring; Home returns to the portfolio landing experience.

## Test 3 - Browse curated work without embedded app prompts
Viewport: mobile
Covers: curated project gallery, lightweight project covers, hosted project links
Description: Verifies the Home gallery uses clean project covers instead of embedded application frames.

Steps:
1. Scroll to Browser experiments
2. Inspect the six curated project covers
3. Open the first experiment

Expected: Six clean project covers are visible with no embedded frame or install card, and the selected experiment opens.

## Test 4 - Preserve Monitoring access
Viewport: desktop
Covers: monitoring navigation, existing runtime information
Description: Verifies Monitoring remains accessible after Home becomes the primary route.

Steps:
1. Select Monitoring
2. Inspect the monitoring heading
3. Return to Home

Expected: Monitoring displays its device/runtime information and Home remains available from primary navigation.
